# Регламент работы с репозиторием проекта «Система бронирования отелей»

## 1. Ветвление

- Основная ветка — `main`. Ветка защищена: прямой push запрещён, изменения
  попадают в неё только через Pull Request.
- Для каждой задачи создаётся отдельная ветка с префиксом по типу работ:
  `feature/booking-form`, `bugfix/payment-error`, `docs/architecture-update`.
- Ветка живёт не дольше одной задачи; после слияния она удаляется.

## 2. Перед началом работы

```bash
git checkout main
git pull origin main
git checkout -b feature/<название-задачи>
```

## 3. Во время работы

- Коммиты атомарные: один коммит — одно логическое изменение.
- Сообщение коммита оформляется по Conventional Commits:
  `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`.
- Не реже одного раза в день — синхронизация с основной веткой:
  `git pull --rebase origin main`.

## 4. Перед push

```bash
git fetch origin
git pull --rebase origin main   # конфликты разрешаются локально
git push origin feature/<название-задачи>
```

## 5. Код-ревью

- Создаётся Pull Request в `main`, назначается ревьюер — второй разработчик.
- Ревьюер проверяет логику, тесты и соответствие требованиям.
- Слияние выполняет автор PR после одобрения (squash-merge).

## 6. Тестирование и CI/CD

- На каждый push в любую ветку CI автоматически собирает проект и запускает
  тесты (`pytest`).
- Сборка основной ветки публикуется в тестовый контур, тестировщик получает
  уведомление в корпоративном мессенджере (Slack/Telegram).
- Красная сборка блокирует слияние PR.

## 7. Разрешение конфликтов

1. Обнаружение: `git merge` / `git pull` сообщает о конфликте.
2. Просмотр: `git status` — список конфликтующих файлов.
3. Анализ маркеров `<<<<<<<`, `=======`, `>>>>>>>` в файле.
4. Совместное решение авторов изменений: какой вариант оставить или как
   объединить.
5. `git add <файл>` и `git commit` (сообщение `merge: ...`).
6. Проверка: тесты зелёные, функциональность не нарушена, затем push.

## 8. Запрещено

- `git push --force` в `main`.
- Коммиты с сообщениями вида «fix», «update», «правки».
- Хранение в репозитории секретов, паролей и ключей доступа.
